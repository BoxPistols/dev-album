# specs/learning-how-to-learn.md — 「学び方」マニュアル

## 目的

初めての領域に入るときの手順そのものを教材にする。個別の技術ではなく、
**どう調べ、何を信じ、どこで確かめ、どう続けるか**を扱う。

既存の 10 マニュアルはすべて「何を学ぶか」で分かれている。そこに入る前段が無く、
学習者は「まず何から手を付けるか」を各自の経験に任されていた。この教材は
その前段を担い、**マニュアル一覧の先頭に置く**。

## なぜ必要か（執筆の動機）

この教材の書き手は、専門的な学歴もオフィスワークの職歴も持たず、パソコンに触れた
経験も無いまま、社会に出て 15 年以上たってから職業訓練で IT を学び始めた。
そのため「学び方そのもの」を最初に覚える必要があった。

> 本人の記事（一次情報）: URL を確認中。現行の
> `https://www.wantedly.com/users/80521411/post_articles/192864` は 404 を返す。
> 本文を教材に引くときは、本人の記事であることを明示したうえで出典を付ける。

この背景を教材に書くかどうかは本人の判断に委ねる。仕様としては「1 ページ目に
なぜこの章があるかを述べる枠を用意する」までを定義する。

## 対象読者

- 未経験からこの分野に入る人（この教材の主要読者）
- 経験はあるが、初めての領域に入るたびに手探りになる人

## 事実の扱い

この教材は「調べ方」を教えるので、**自分が書いた内容の裏取りが緩いと成立しない**。

- 検索演算子は Google の公式ヘルプに載っているものだけを「使える」と書く。
  実測で動くが未文書のもの（`inurl:` `intitle:` `AROUND()` など）は
  「文書化されていないので将来止まりうる」と明記して区別する
- 一次情報の例に挙げる URL はすべてフルパスで、実在を確認してから載せる
- AI の挙動は製品によって変わるため、断定せず「確かめる手順」の形で書く

## 他マニュアルとの関係

- 事実確認と検証の型は Claude Code マニュアルの
  `/claude-code/best-practices/verification-and-trust` と重なる。あちらは
  「エージェントの出力を信頼する条件」、こちらは「自分の理解を確かめる方法」。
  相互にリンクし、内容は重複させない
- `/claude-code/multi-ai/file-map` と同様に、比較は表で示す

## やらないこと

- 学習法の一般論（記憶術、時間管理）は扱わない。技術領域に入るときの手順に絞る
- 特定の有料サービスの推奨はしない
- 精神論を書かない（「諦めなければできる」等）
