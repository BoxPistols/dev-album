## 前提: 判定を層で分ける

プロンプトで「正確に引用して」と頼むだけでは捏造・言い換えを検出できない。
**決定的に取れるものを判断に回さない**。この順で当てる。

| 層 | 何を見るか | 手段 | 誤検出 |
|---|---|---|---|
| L1 | 出典レジストリの書式 | `pnpm test src/data/sources.test.ts` | なし |
| L2 | 逐語引用が原文にあるか | `pnpm check:sources` | なし |
| L3 | 監査の判定に書いた引用が原文にあるか | `pnpm check:verdicts <判定JSON>` | なし |
| L4 | 実測の再現性 | `reproduce` コマンドを手で回す | なし |
| L5 | レジストリに載っていない主張 | ここで初めて読んで判断する | あり |

L1〜L4 が緑になるまで L5 をやらない。順序を逆にすると、機械で落とせるものを
人が読んで見逃す。

## 判定の引用は「装飾なしの逐語 1 本」で書く

`docs/audits/*-verdicts.json` の `quote` は、L3 が原文と文字列一致で照合する。
次を入れると、判定自体が正しくても照合に落ちる。

- 出典ラベルの前置き（`RFC 9112 Section 2.1: "..."`、`[https://...] "..."`）
- ページ名の付加（`【quick-start.html】「...」`）
- 引用符での囲み（原文自体に含まれる場合を除く）
- 複数箇所・複数ページの引用を `/` や改行で連結したもの
- 表のセルやコードブロックを詰めて 1 行にしたもの
- 自分の注記（`(略、同 README の別節)`）

2 箇所必要なときだけ中略記号 `[…]` で繋ぐ。原文の言語のまま貼る（訳さない）。

**この書式を指示しないと 4 分の 1 が照合できなくなる。** 実測で、書式を指示せずに
判定した 547 件は 74% しか一致せず、指示した 386 件は 99% 一致した。差は判定の質
ではなく引用の書き方だけだった。

一致しなかった引用は、出典を取り直して選び直す。その過程が判定の再検証になる
（169 件を書き直したとき、判定が変わったものが 2 件あった）。

## 手順

### 1. 機械で取れるものを取る

```bash
pnpm test src/data/sources.test.ts   # レジストリの書式
pnpm check:sources                   # 実際に URL を取得して逐語照合
```

`check:sources` が「引用が本文に見つからない」と言ったら、原因は 2 つに 1 つ。

- **原文が変わった**: 一次情報を読み直し、引用と本文の記述の両方を更新して `verifiedAt` を今日にする
- **引用が正確でなかった**: 本文の主張ごと見直す。引用を原文に合わせて直すだけで済むとは限らない

**引用を通すために正規化を緩めない。** `normalize()` が吸収してよいのは
バッククォート・Markdown リンク記法・`<code>` 境界の空白・引用符の字体まで。
語を落とす正規化を足すと、言い換えた引用が通るようになり仕組みが死ぬ。

### 2. 実測の主張を再現する

`kind: "measured"` の出典は `check:sources` が再現コマンドを一覧表示する。
バージョンを固定したまま実際に回し、`note` の記述と一致するか確かめる。

一致しなくなっていたら、それは**上流が直った**ということ。教材から落とすか、
「どの版で再現し、どの版で直ったか」を書く。黙って残さない。

### 3. レジストリに載っていない主張を洗い出す

対象ページを読み、事実を主張している文を拾う。次に当たるものは要注意。

- ツールの挙動（「〜が自動的に読む」「〜すると再読込される」）
- 数値（行数・件数・比率・バージョン）
- 「公式が推奨している」「標準化が進んでいる」
- 全称・存在の否定（「〜するツールはない」「必ず〜になる」）

拾った文ごとに次を判定する。

- 一次情報がある → レジストリに逐語引用つきで足す
- 自分で再現できる → 実際に回して `kind: "measured"` で足す
- 他者の測定に依る → `kind: "secondary"` にし、**本文にも引用であることを書く**
- どれでもない → **書かない**。断定を弱めるのではなく、その文を落とす

### 4. 「分からない」を残す

一次情報に当たっても確定しなかった項目は、確定しなかったと書く。
`「公式に該当記載なし」` は正当な結論であって、埋めるべき欠落ではない。

推測で埋めた一文は、読者からは確認済みの記述と見分けがつかない。
「分からない」と書かれた読者は別の手段を探すが、断定された読者は何もしない。

## 禁止

- 要約・翻訳を `quotes` に入れる（訳す場合は本文側で「訳は筆者」と明記して原文を併記）
- 相手が言っていない言い回しを引用符の中に入れる
- 二次情報を一次情報として提示する
- `verifiedAt` を実際に照合せずに更新する
- 検証が落ちたときに、検証のほうを緩めて通す

## 落とし穴

- **0 件で成功するチェックを信用しない。** レジストリの解析に失敗して空配列を返せば
  「照合 0 件・失敗 0 件」で緑になる。`verify-sources.mjs` は 0 件を事故として投げる
- **新しい検査は一度壊して赤を見る。** 偽の引用を仕込んで落ちることを確認してから信用する
  （捏造・言い換え・語の脱落・数値改変・離れた 2 文の無断連結の 5 種で試すとよい）
- **`cmd | tail` の終了コードは `tail` のもの。** 成否は出力の中身で確認する
- **不一致が大量に出たら、まず検査側を疑う。** 実測で、不一致 207 件のうち大半は
  引用の誤りではなく取得・正規化の取りこぼしだった。数を人に出す前に、
  実際に何件かを原文と突き合わせる
- **一致しないものを黙って「一致」にも「不一致」にも混ぜない。** 平文化できない
  （PDF で `pdftotext` が無い等）ものは未照合として別に数える。道具の不在と
  引用の誤りは別の問題で、混ぜると片方が見えなくなる
- **取得側の癖で偽の不一致が出る。** 実際に踏んだもの:
  - GitHub の blob ページは本文が JS 埋め込みなので raw を引く
  - ブラウザを騙る UA を弾く出典がある（w3.org は素直な UA なら 200）
  - meta refresh は fetch が追わない（nuxt.com は本文が 125 字で終わる）
  - 言語を指定しないと別言語版が返る（web.dev がポーランド語版を返した）
  - Wayback は連続アクセスで 503 を返す。再試行すると通る
- **まとめて回した結果の失敗は、個別に再実行して確かめる。** 一時的な取得失敗が
  混ざる。1 件だけ落ちたときは特に疑う
